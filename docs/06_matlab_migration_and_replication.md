# MATLAB BLINKER Migration and Replication

## Purpose
`pyblinker` is fundamentally grounded in the logic of the original MATLAB-based **BLINKER** toolbox. A primary goal of this repository is to offer a Python implementation that replicates the BLINKER pipeline's results, ensuring that researchers can migrate their workflows to the open-source Python ecosystem without losing continuity with previous studies.

> **Original Citation:**
> K. Kleifges, N. Bigdely-Shamlo, S. E. Kerick, K. A. Robbins (2017).
> BLINKER: Automated Extraction of Ocular Indices from EEG Enabling Large-Scale Analysis.
> *Frontiers in Neuroscience*, 11, Article 12.
> [https://doi.org/10.3389/fnins.2017.00012](https://doi.org/10.3389/fnins.2017.00012)

## The Replication Pipeline
The migration effort involves a strict 1:1 port of the core algorithmic steps. We validate this by running the original MATLAB code on sample data, saving the intermediate matrices (e.g., candidate signals, fitted shapes, blink positions), and ensuring the Python functions produce identical outputs (within floating-point tolerance).

## Key Modules
The core ported logic resides in:

*   **`pyblinker/blinker/`**: Contains the direct ports of the MATLAB functions.
    *   `get_blink_positions.py`: Implements the "Step 1" logic: calculating the robust standard deviation (MAD) of the candidate signal, applying thresholds, and merging nearby candidates to find rough blink intervals.
    *   `fit_blink.py`: The core "Step 2" module. It fits "tent" (linear) and "bell" (Gaussian/polynomial) shapes to every detected blink to determine precise landmarks like the peak, left/right zero crossings, and slopes.
    *   `get_representative_channel.py`: Implements "Step 3". It decides which channel to use for blink detection by analyzing all channels' statistics (SNR, number of good blinks) and selecting the best one (typically a frontal channel like Fp1/Fp2).
    *   `base_left_right.py`: Computes the "base" of the blink (where the blink deviation starts/ends relative to the velocity profile). This is critical for defining the full duration of the blink.
    *   `fit_range.py`: Determines the exact sample ranges to use for the left and right slope fitting. It ensures that the fit ignores the noisy "tails" of the blink.
    *   `stroke_utils.py`: Utilities for analyzing the up-stroke (closing) and down-stroke (opening) phases of the blink, finding frames of maximum velocity.
    *   `blink_epoch_mapper.py`: Handles the mapping of continuous blink events to MNE epochs. It includes logic for "majority voting" when a blink straddles two epochs.
    *   `default_setting.py`: Contains the canonical constants (e.g., `std_threshold=1.5`, `SCALING_FACTOR=1.4826`) used by the legacy MATLAB code.

*   **`pyblinker/fitutils/`**: Helper math functions required to match MATLAB's numerical behavior.
    *   `forking.py`: Contains direct ports of MATLAB's `polyfit`, `polyval`, `mad` (Median Absolute Deviation), and `corr` functions. These are necessary because Python's `numpy.polyfit` or `scipy.stats` sometimes handle edge cases or normalization differently than MATLAB.
    *   `line_intersection.py`: Computes the intersection of two fitted lines (the "tent" shape). It returns the intersection point (peak) and the x-intercepts.
    *   `ear_crossing.py`: (Newer addition) Provides robust threshold crossing logic for EAR signals, using linear interpolation to find sub-sample crossing times.

## Validation Strategy
The `test/blinker_migration` folder contains a specialized test suite. These tests load ground-truth data generated by the MATLAB toolbox (stored in `test/migration_files/*.mat`) and assert that the Python functions generate the same output.

### Seamless Blink Feature Replay (Path Resolution)
This migration helper now ensures the repository root is added to `sys.path` when executing the standalone replay script so that the `pyblinker.blink_features` package imports correctly without an editable install. The replay script also resolves the example data file from `tutorial/blinkprops_case01.pkl` to avoid reliance on the current working directory.

### Unit Tests
*   **`test/blinker_migration/test_step1a.py`**: Validates candidate signal generation. It compares the raw signal vector used for detection against the MATLAB export.
*   **`test/blinker_migration/test_step1bii_fitblink.py`**: Checks the shape fitting algorithm. It verifies that `fit_blink.py` produces the same $R^2$ values and slope parameters as the MATLAB `fitBlink` function.
*   **`test/blinker_migration/test_step2b_getGoodBlinkMask.py`**: Verifies the logic that accepts/rejects blinks. It ensures that the "Good Blink" binary mask is identical, meaning Python accepts the exact same set of blinks as valid.
*   **`test/blinker_migration/test_zero_crossing.py`**: Ensures zero-crossing indices match exactly. A difference of even one sample here would ripple through all downstream velocity calculations.
*   **`test/blinker_migration/test_step3_select_channels.py`**: Validates that given a multi-channel recording, the Python code picks the same "best" channel as MATLAB.

### Tutorials
*   **`tutorial/02b_extract_blink_from_matlab_blinker.py`**: A complete script showing how to run the ported "legacy" pipeline.
*   **`tutorial/blinker/migration/`**: Contains scripts that visualize the comparison between MATLAB and Python outputs step-by-step.
